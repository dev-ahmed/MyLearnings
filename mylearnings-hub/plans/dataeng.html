How to run this

01

Land raw, immutable data first (ELT). You can always re-derive transforms; you can't un-delete the source. Raw is the source of truth.

02

Make every write idempotent. Re-runs and backfills are routine, not emergencies — overwrite-by-partition or upsert-on-key.

03

Model transformations as tested, version-controlled code (dbt). One definition of each metric, reviewed and tested.

04

Validate data at the boundary and fail fast. Silently wrong data is worse than a loud failure — catch it at ingestion.

05

Reach for big tools only at big scale. Most data isn't big data — pandas/DuckDB + a warehouse beats Spark/Kafka until it genuinely can't.

06

Rhythm: ~4 hrs/day × 3 days, always against a real source landing into a warehouse. Pipelines are learned by running them.
