How to run this

01

RAG is 80% search. Strip away the LLM and it's an information-retrieval pipeline — your ETL, indexing, and relevance instincts are the ones that matter.

02

Debug retrieval first. Most 'the model is dumb' bugs are 'the right chunk was never retrieved'. Fix retrieval before the prompt.

03

Measure everything. Build a golden set early; every change is gated by a number, not a vibe. Evaluation is the whole skill.

04

Ground hard. Use-only-context, cite sources, and always allow 'I don't know' — a confident wrong answer is the core failure mode.

05

Build on your infra. Redis for caching, queues for ingestion, FastAPI to serve — the companion cookbooks are the substrate.

06

Rhythm: ~3 hrs/day × 5 days. End each day with a query you can run and a chunk you can inspect.
