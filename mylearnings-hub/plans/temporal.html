How to run this

01

Kill the worker on purpose. The only way to believe durable execution is to watch a workflow survive Ctrl-C mid-run. Do it every week.

02

Workflows decide, activities do. If you're unsure where code goes, ask: does it touch the outside world? Then it's an activity.

03

Read the event history. The Web UI's history is the truth. When something surprises you, open it before opening the code.

04

Idempotent by default. Assume every activity runs twice. Design the key before writing the call.

05

Test with time travel. Use the time-skipping test environment so 7-day timers take milliseconds. Slow tests don't get written.

06

Rhythm: ~1.5 hrs × 4 sessions a week: one to read, two to build, one to break things and fix them.
