How to run this

01

One app, all 3 weeks. Add caching, then jobs, then tested mail to a single API — each week is a layer on the same project, nothing throwaway.

02

Redis is the spine. It's the cache, the lock, the rate limiter, and the queue broker. Get comfortable with it in week 1 and the rest builds on it.

03

Assume it runs twice. Everything async can be redelivered — make every job and effect idempotent. It's the discipline that separates working from correct.

04

Both languages. Do each build in your stronger stack first (Node), then port the core to Python (redis-py + Celery/RQ) to cement it.

05

Make it visible. Stand up dashboards and Mailpit early — you can't operate what you can't see, and async has no request to watch.

06

Rhythm: ~3 hrs/day × 5 days. End each day with something running you can hit — a cached endpoint, a drained queue, a captured email.
