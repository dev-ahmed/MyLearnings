How to run this

01

Most problems aren't RL problems. Learn the five-point test cold — a rule, a forecast, or a bandit beats RL most of the time. Knowing when NOT to use it is the skill.

02

Don't hand-roll the algorithms. Use Gymnasium + Stable-Baselines3; implement from scratch only to learn the idea, never to ship. Start every project with stock PPO.

03

The reward is the program. The agent optimises exactly what you reward, loopholes included. Design it against an adversary and watch behaviour, not just the curve.

04

Report across seeds. One run is an anecdote; RL results are distributions. 3–5 seeds, mean ± std, always.

05

Deploy frozen, with a fallback. Train offline, clamp actions, keep a non-RL baseline to beat and to fall back to.

06

Rhythm: ~4 hrs/day × 3 days. End each session watching a reward curve climb — the fast feedback loop is the whole joy of RL.
