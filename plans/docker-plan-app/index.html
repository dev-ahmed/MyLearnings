How to run this

01

Containerize your own apps. Don't practice on toy images — dockerize the FastAPI/Node projects you're already building. Real problems teach faster.

02

Build small, build often. Smaller images deploy faster and expose less. Watch your image size shrink week over week.

03

One process per container. A container runs one job; compose the rest. State lives in volumes and databases, never the container.

04

Never bake secrets in. Pass config and secrets at runtime, pin base-image versions, and keep a lean .dockerignore.

05

Read the layers. Every Dockerfile line is a cached layer — order them cheap-to-expensive so rebuilds stay fast.

06

Rhythm: ~3 hrs/day × 5 days. End each day with a container you can actually run and hit from your browser.

Core commands to memorize

Images

docker build -t app:1.0 . docker images docker tag app:1.0 user/app:1.0 docker push user/app:1.0 docker pull user/app:1.0

Run & inspect

docker run -d -p 8080:80 app docker ps / docker ps -a docker logs -f <container> docker exec -it <container> sh docker stop <c> / docker rm <c>

Compose

docker compose up -d --build docker compose ps docker compose logs -f docker compose down # -v wipes volumes

Cleanup & disk

docker system df docker image prune docker volume ls docker system prune -af
