Before you start

What you should already know — shore up any gaps first:

  • Comfortable with Docker and containers (the Docker plan)
  • Basic YAML and command-line comfort
  • Understand services, ports, and load balancing
  • A cloud account is optional — a local cluster (kind/minikube) is enough

How to run this

01

You probably don't need Kubernetes. Use the lowest rung — PaaS, managed endpoint, managed k8s — that runs your workload. Learn it anyway; it's everywhere.

02

Declare desired state; let it converge. Edit YAML and apply; don't hand-run imperative changes in prod. It's a control loop, not a script.

03

Set requests/limits and the right probes. Especially a startup probe for model loading — most cluster pain traces here.

04

Scale both layers, with caps. HPA (pods) + cluster autoscaler (nodes); scale GPUs to zero; bound the max so a spike can't run away.

05

Watch cost and health. Idle GPUs and over-requests are the bill — monitor, right-size, and cap, or let a managed platform do it.

06

Rhythm: ~4 hrs/day × 3 days on a local cluster (kind/minikube/k3s). No cloud bill needed to learn the core.
